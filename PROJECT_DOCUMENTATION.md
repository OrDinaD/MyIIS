# Полная документация проекта MyIIS

## 1. Обзор проекта
**MyIIS** — это современное iOS-приложение для студентов БГУИР, написанное на **Swift 6** с использованием **SwiftUI**. Приложение взаимодействует с API `iis.bsuir.by` для предоставления доступа к расписанию, оценкам, рейтингу, электронным студенческим сервисам, данным об общежитии и библиотеке. 

## 2. Архитектура и Паттерны
Приложение построено по строгой архитектуре **MVVM (Model-View-ViewModel)**.

*   **UI (Пользовательский интерфейс):** Полностью реализован на SwiftUI.
*   **Бизнес-логика (Services):** Выделена в сервисы (например, `APIService`, `AuthenticationService`), которые работают как синглтоны или передаются через внедрение зависимостей (Dependency Injection).
*   **Состояния (ViewModels):** Связывают модели данных и SwiftUI-представления (Views), обрабатывая логику отображения данных.
*   **Асинхронность:** Активно используется современный Swift Concurrency (async/await).
*   **Навигация:** Централизованная маршрутизация через класс `AppRouter` с использованием `NavigationPath`.

## 3. Структура проекта и расположение файлов

Основной код приложения находится в директории `MyIIS/`. Дополнительные расширения — в `MyIISWidget/` (Виджет) и `MyIISIntents/`. Общий код — в `Shared/`.

### 🗂 `/MyIIS/Models/` (Модели данных)
Содержит структуры (обычно `Codable`), отражающие ответы API и бизнес-сущности:
*   `User.swift`: Главная модель пользователя (студента).
*   `Gradebook.swift`, `Markbook.swift`: Модели для электронных зачеток и оценок.
*   `StudyPlan.swift`: Данные учебного плана студента.
*   `APIAttendanceModels.swift`: Данные по посещаемости.
*   `RatingModels.swift`: Рейтинг студента.
*   `DormitoryModels.swift`: Информация по общежитиям.
*   `LibraryItem.swift`: Данные из библиотеки.
*   `LMSCourse.swift`: Интеграция с СЭО (Moodle).
*   *(А также файлы: AccountSettingsModels.swift, Activity.swift, Announcements.swift, DiplomaApplication.swift и другие).*

### 🗂 `/MyIIS/Services/` (Сервисы и бизнес-логика)
Выполняют сетевые запросы, парсинг данных и управление состоянием приложения.
*   `APIService.swift` / `APIService+...`: Главный класс для работы с API БГУИР. Обрабатывает HTTP-запросы и ошибки.
*   `AuthenticationService.swift`: Управляет авторизацией (вход, выход, хранение сессии пользователя).
*   `CredentialStore.swift`: Безопасное хранение логина и пароля в iOS Keychain.
*   `URLFactory.swift`: Построитель URL для запросов.
*   `LMSService.swift`: Сервис для работы с СЭО.
*   *(А также узкоспециализированные сервисы: DormitoryService, LibraryService, PenaltiesService, StudyService, SettingsService и т.д.).*

### 🗂 `/MyIIS/ViewModels/`
Классы, отвечающие за подготовку данных для Views. Наблюдаемые (Observable) объекты.
*   `AccountSettingsViewModel.swift`: Логика экрана настроек аккаунта.
*   *(И другие ViewModel-классы для соответствующих экранов).*

### 🗂 `/MyIIS/Views/`
SwiftUI компоненты. Обычно разделены на сам экран (View) и вспомогательные элементы (`+Helpers`).
*   `ContentView.swift` / `MyIISApp.swift`: Точка входа в приложение и корневое представление.

### 🗂 `/Shared/`
Общий код между основным приложением и расширениями (виджетами):
*   `AppNavigation.swift`, `AppTab.swift`: Маршрутизация и структура табов.
*   `AppTheme.swift`, `Color+Extensions.swift`: Глобальные стили, шрифты и цвета.
*   `MyIISDataStore.swift`: Механизм совместного использования данных через App Groups (например, для виджета).

### 🗂 Расширения (Extensions)
*   **`/MyIISWidget/`**: `AttendanceWidget.swift` — код iOS-виджета для отображения посещаемости на главном экране устройства.
*   **`/MyIISIntents/`**: App Intents для интеграции приложения с системой iOS (Shortcuts, Siri).

## 4. API и Эндпоинты

**⚠️ ВАЖНО:** Официальная документация SwaggerHub устарела и не соответствует действительности. Фактически рабочие эндпоинты описаны в файле `/API/REAL_API_ENDPOINTS.md`.

*   **Базовый URL:** `https://iis.bsuir.by/api/v1` (не v2!).
*   **Аутентификация:** Используется **Cookie-based** авторизация (не JWT).
    *   При вызове `POST /api/v1/auth/login` (body: `username`, `password`) сервер возвращает 200 OK и устанавливает Cookie `SESSION`.
    *   Все последующие запросы используют эту Cookie автоматически через `URLSession`.

**Основные эндпоинты:**
*   `POST /api/v1/auth/login`: Вход в систему.
*   `GET /api/v1/personal-information`: Получение профиля студента (ФИО, факультет, группа).
*   `GET /api/v1/schedule`: Расписание занятий.
*   `GET /api/v1/markbook`: Оценки.

## 6. Ограничения и известные проблемы (Constraints & Issues)

1.  **Проблема с документацией SwaggerHub:** Разработчикам строго необходимо ориентироваться на `REAL_API_ENDPOINTS.md` в папке `/API`, так как сервер IIS использует v1 API с Cookies, а не v2 с Bearer-токенами.
2.  **Нестабильность API IIS:** Сервер может периодически отвечать кодом `418 I'm a teapot` (сервис недоступен / технические работы). Код приложения должен это корректно обрабатывать.
3.  **Безопасность конфигурации:** Для локального запуска и прохождения тестов API требуется настройка `.env` файла (`IIS_USERNAME`, `IIS_PASSWORD`). Эти учетные данные никогда не должны попадать в систему контроля версий Git.
4.  **Legacy-особенности:** Некоторые эндпоинты (например, в зачетке) имеют резервные пути, так как для ряда студентов БГУИР основные эндпоинты могут отдавать 404.
